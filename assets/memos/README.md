# 메모

그때그때 한 일, 회의에서 나온 말, 떠오른 생각을 바로 적어 두는 곳입니다. 메모는 정리된 문서가 아니라 **재료**입니다. 에이전트가 주간 보고나 다른 문서를 쓸 때, 고른 메모를 읽고 정해진 형식으로 옮깁니다.

## 1. 쓰기

| 할 일 | 하는 법 |
| --- | --- |
| 바로 한 줄 남기기 | 목록 위 **빠른 메모** 칸에 쓰고 Enter. `#회의`처럼 쓴 낱말은 태그가 됩니다. 왼쪽에서 업무나 태그를 고른 채로 쓰면 그 업무·태그가 붙습니다 |
| 제대로 쓰기 | **＋ 새 메모**(N). 제목(비우면 첫 줄), 업무, 태그, 본문(Markdown: `## 제목`, `- 목록`, `- [ ] 할 일`, `**굵게**`, `` `코드` ``) |
| 하루 일지 | **오늘 메모**: `YYYY-MM-DD 업무 일지`(태그 `일지`)를 열거나 만듭니다. 한 일 · 결과 · 다음 칸이 들어 있습니다 |
| 저장 | 쓰는 대로 저장됩니다(위에 "저장됨 시:분"). GitHub에 저장하는 프로젝트는 타자를 멈춘 뒤(2.5초) 한 번씩 저장해 커밋이 하나씩 생깁니다. 저장이 안 되면 이 브라우저에 보관했다가 다시 시도합니다 |
| 어디서 | 아래 §4. GitHub 저장이면 배포된 사이트에서 PC·휴대폰 어디서나, 아니면 이 PC의 문서 미리보기에서 |

**업무**는 주간 보고의 업무 이름(= 로드맵의 업무 묶음)과 같게 씁니다. 입력 칸이 로드맵과 지난 보고의 업무 이름을 제안합니다. 업무가 같으면 주간 보고에서 한 절로 모입니다.

## 2. 정리하기

| 기능 | 설명 |
| --- | --- |
| 모아 보기 | 모든 메모 · 고정 · 오늘 · 최근 7일 · 업무 미지정 · 보관함 · 휴지통, 업무별, 태그별(`회의/주간`처럼 `/`로 나누면 묶여 보임) |
| 찾기 | 제목·본문·업무·`#태그`·메모 번호에서 찾습니다(`/`). 보관한 메모도 찾기에는 나옵니다. 작성일 범위와 정렬(고친 순, 쓴 순, 제목 순) |
| 고정 · 보관 · 휴지통 | 고정은 목록 맨 위. 보관은 목록에서 숨김(지우지 않음). 휴지통에서 되살리거나 완전히 지웁니다 |
| 여러 개 한꺼번에 | 목록의 체크 칸(또는 Ctrl/⌘·Shift+클릭)으로 고른 뒤 업무 지정, 태그 더하기, 보관, 휴지통 |
| 체크 목록 | 미리보기(Ctrl/⌘+Enter)에서 `- [ ]` 칸을 누르면 바로 체크됩니다 |

## 3. 에이전트에게 넘기기

1. 목록에서 참고할 메모를 고릅니다(업무·태그·기간으로 거른 뒤 **모두 고르기**도 됩니다).
2. **에이전트에게 넘기기** → 주간 보고 / 다른 문서를 고르고 **복사** → 에이전트 대화에 붙여 넣습니다.
3. 에이전트는 그 메모만 읽어서 씁니다. 주간 보고라면 메모를 업무별로 모아 보고 형식(배경 · 한 일 · 결과 · 다음)으로 옮기고, 보고 머리말 `memos:`에 참고한 메모 번호를 남깁니다.

메모를 고르지 않고 "알아서 써 줘"라고 하면, 에이전트는 예전처럼 그 기간의 커밋·이슈·작업 내역에서 재료를 모읍니다. 메모의 날짜가 보고 기간 안에 있을 필요는 없습니다. 고른 메모가 곧 그 보고의 범위입니다.

에이전트가 쓰는 명령(사람이 직접 써도 됩니다):

```bash
.docs-kit/bin/memos.py list --work "시뮬레이션 환경" --since 2026-11-01   # 고를 메모 찾기
.docs-kit/bin/memos.py show 20261121-153012 20261120-090000            # 메모 읽기
.docs-kit/bin/weekly_draft.py --memos 20261121-153012 20261120-090000  # 그 메모로 주간 보고 재료 (+ --write 뼈대)
```

## 4. 어디에 저장되나

메모 하나 = 파일 하나 `<번호>.md`(번호 = 쓴 시각 `YYYYMMDD-HHMMSS`)입니다. 머리말에 제목·업무·태그·고정·보관·휴지통, 본문은 Markdown입니다. 프로젝트가 `docs-kit.yml`로 저장 방식을 고릅니다(위 메모 앱의 ⚙에서 지금 방식을 봅니다).

### 4.1 GitHub 저장 (어느 기기에서나)

`docs-kit.yml`에 `memos.github`가 있으면 메모는 그 GitHub 저장소(비공개로 만듦)의 파일입니다. 배포된 사이트의 메모 앱이 브라우저에서 GitHub에 바로 저장하므로, 미리보기를 켤 필요 없이 PC와 휴대폰 어디서나 씁니다.

```yaml
memos:
  github: {repo: <계정>/<프로젝트>-memos}   # branch: main, path: ''(저장소 맨 위)이 기본
  dir: private/memos                        # 에이전트가 읽는 이 PC의 복제본 (.gitignore에 넣음)
```

- **기기(브라우저)마다 한 번 연결**합니다: 메모 앱의 **GitHub 연결** → 안내대로 GitHub에서 토큰을 만듭니다(그 저장소 하나만, Contents 읽기·쓰기) → 붙여 넣기. 토큰은 그 브라우저에만 저장되고 GitHub 말고 어디로도 가지 않습니다. 공용 PC에서는 쓰지 않고, 기기를 잃어버리면 GitHub 설정에서 토큰을 지웁니다. 연결 끊기는 ⚙.
- 두 기기에서 같은 메모를 고치면, 나중에 저장하는 쪽이 덮어쓰지 않고 어느 쪽을 남길지 묻습니다(GitHub이 파일 버전을 확인). 다른 메모는 함께 써도 됩니다.
- 에이전트는 이 PC의 복제본(`memos.dir`)을 읽고, 읽기 전에 `git pull`을 저절로 합니다(`memos.py`, `weekly_draft.py --memos`). 처음 한 번: `git clone git@github.com:<계정>/<프로젝트>-memos.git private/memos`.
- 저장소는 비공개로 둡니다. 배포된 사이트와 프로젝트 저장소에는 메모가 나타나지 않습니다.

### 4.2 이 PC에 저장 (미리보기)

`memos.github`가 없으면 메모는 `memos.dir`(기본 `docs/memos/`) 폴더의 파일이고, **이 컴퓨터의 문서 미리보기에서만** 씁니다(`.docs-kit/bin/docs.sh start` → `http://localhost:8000/…/memos/app/`). 다른 PC에서 IP 주소로 연 미리보기와 배포된 사이트는 읽기·쓰기를 막습니다. 편집기로 파일을 직접 고쳐도 되고, 앱은 고친 내용을 다시 읽습니다. git에 넣을지는 프로젝트가 정합니다(공개 저장소면 커밋한 메모도 공개이므로 `memos.dir`을 git이 무시하는 폴더로).

### 4.3 공통

- 메모는 사이트 페이지로 만들어지지 않고, 문서 검색(`docs_search.py`)·근거 점검·문서 지도에도 들어가지 않습니다(메모는 근거가 아니라 재료).
- 4.2 방식에서 배포된 사이트에 메모 사본을 싣으려면 `memos: {publish: true}`(읽기만, 기본은 싣지 않음).
