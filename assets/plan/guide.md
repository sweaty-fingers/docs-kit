# 현황판 편집 안내

현황판은 파일 세 개로 만들어집니다. 그림·표·트리는 빌드할 때 이 파일들에서 다시 그려지므로, 계획이 바뀌면 파일만 고칩니다(docs-kit `hooks/plan.py`).

| 파일 | 담는 것 | 고치는 때 |
| --- | --- | --- |
| `docs/plan/scope.yml` | 단계와 일의 분해(Epic > Feature > Story > Backlog > WBS), 크기, 통과 기준·완료 정의, 연구 질문 | 계획이 바뀔 때 |
| `docs/plan/risks.yml` | 리스크 대장: 가능성·영향, 대응, 담당, 상태, 평가 이력 | 리스크를 다시 평가할 때 (주간 보고 때 권장) |
| `docs/plan/issues.json` | 이슈 트래커 상태 스냅숏 (선택) | 프로젝트의 내보내기 스크립트로 새로 받음 (주간 보고 때). 형식은 §6 |
| `docs/plan/sprints.json` | 스프린트: 기간, 목표, 카드와 칸, 막힘, 이월, 회고 | 스프린트 보드에서 끌어 옮기면 저장 (§5) |

## 1. 단계와 일의 분해 (`scope.yml`)

평평한 목록입니다. 항목을 다른 곳으로 옮기려면 `parent`만 바꿉니다.

```yaml
- {id: M0, level: epic, kind: deliver, wave: now, title: M0 인프라, dod: [{text: "통과 기준", met: partial, evidence: [VR-0003]}]}
- {id: F.login, level: feature, parent: M0, title: 로그인}
- {id: B.61, level: backlog, parent: F.login, issue: 61, wave: next, dod: ["실제 계정으로 로그인을 VR로"]}
- {id: W.sso, level: wbs, parent: B.61, roadmap: sso, size: [3, 5], added: 2026-11-17}
```

| 키 | 뜻 |
| --- | --- |
| `level` | `epic`, `feature`, `story`, `backlog`, `wbs` |
| `size` | 포인트(1 ≈ 이상적인 하루 작업). 숫자 하나, 또는 먼 일은 폭 `[최소, 최대]`. **한 갈래에서 한 번만** 적습니다(자식이 있으면 자식에, 또는 부모에만) |
| 상태 | `roadmap: <로드맵 id>`(상태·날짜를 로드맵에서) / `issue: <번호>`(닫히면 완료) / `status: todo \| doing \| done \| dropped` + `date` |
| `dod` | 완료 정의. Epic은 단계 통과 기준(`met: yes \| partial \| no`, `evidence`), 백로그·WBS는 끝났다고 말할 조건. 없으면 빌드 경고 |
| `added`, `removed` + `reason` | 계획에 들어온 날, 뺀 날과 이유. 작업량 띠와 계획 변경 기록에 반영 |
| `kind` | `deliver`(만들기), `learn`(답 찾기: 시간 상자), `decide`(결정), `enabler`(기반) |
| `wave` | 시기 `now`, `next`, `later`. now는 잘게, later는 폭으로. 위에서 물려받음 |
| `short` | Epic의 짧은 이름(단계 칸에 보임). 없으면 제목의 " - " 앞 |

값에 `, `(쉼표+공백)나 ` #`가 있으면 따옴표로 감쌉니다. `{title: 로그인 (ADR-0003, 0005)}`은 제목이 쉼표에서 잘리고(빌드 경고: 모르는 키), `actions: 추정 #57`은 `#` 뒤가 주석이 되어 사라집니다(경고 없음).

팀 공통 완료 정의는 `team_dod`, 계획을 크게 다시 정한 날은 `baselines`, ID 접두사 설명은 `legend`(`[{key, text}]`, 단계별 진행 위에 보임), 연구 질문은 `questions`(`open`, `investigating`, `answered`, `dropped` + `confidence`, `evidence`)에 둡니다.

## 2. 계획이 바뀔 때

| 바뀐 것 | 고칠 것 |
| --- | --- |
| 일이 끝남 | 로드맵 항목을 `done`으로, 또는 이슈를 닫고 스냅숏. 현황판은 따로 고치지 않음 |
| 새 일이 생김 | 항목을 더하고 `added`에 오늘 날짜 |
| 일을 뺌 | 지우지 않고 `status: dropped`, `removed`, `reason` |
| 먼 단계를 잘게 나눔 (시기가 다가옴) | 폭으로 적은 크기를 지우고 자식 항목들에 크기를 나눠 적음, `wave: now` |
| 계획을 크게 다시 정함 (큰 결정) | `baselines`에 한 줄 (B2 …) |
| 단계 통과 기준을 채움 | Epic `dod`의 `met`과 `evidence` |

## 3. 진척과 예측을 읽는 법

- **작업량 띠**는 그날 계획에 있던 일의 크기 합(최소~최대)입니다. 띠가 위로 움직이면 일이 늘어난 것입니다.
- **끝낸 일**은 끝난 항목의 크기 합입니다(폭으로 적힌 항목은 가운데 값).
- **예측**은 다 지난 주의 처리량(낮음/평균/높음)으로 남은 작업량을 나눈 날짜입니다. 비관은 남은 작업량이 50% 늘어난다고 봅니다. 데이터가 6주 미만이면 신뢰가 낮습니다.
- 지금 하는 일(시기 `now`)과 과제 전체를 탭으로 나눠 봅니다. 먼 단계는 크기가 폭이라 전체 예측은 넓게 나옵니다. 그래프에 마우스를 올리면 그날 숫자가 나옵니다.

## 3.1 화면에서 할 수 있는 것

| 곳 | 동작 |
| --- | --- |
| 요약 카드 | 누르면 해당 절로 이동 |
| 작업량과 진척 | 탭 전환, 마우스를 올리면 날짜·계획 작업량·끝낸 일, 오늘 뒤는 예측 값 |
| 단계별 진행 | 위 단계 칸을 누르면 그 단계로, 찾기(이름·#이슈·완료 정의), 상태·시기 거르기, 모두 펼치기·접기 |
| 연구 질문 | 관련 항목을 누르면 단계별 진행에서 그 항목을 펼침 |
| 리스크 | 등급 카드·PI 매트릭스 칸을 누르면 대장을 거름(다시 누르면 해제), ID에 마우스를 올리면 원인·대응, 대장에서 찾기·분류·상태·등급 거르기, 열 이름을 눌러 정렬, ▼▲에 마우스를 올리면 점수 이력 |

## 4. 리스크 (`risks.yml`)

| 키 | 뜻 |
| --- | --- |
| `history` | `[{date, p, i, note}]` 가능성·영향(1~5) 평가 이력. 마지막 줄이 현재. 바꿀 때 줄을 더하면 추이와 ▼▲가 나옴 |
| `status` | `open`(관리 중), `watch`(지켜봄), `occurred`(일어남: 이슈로 다룸), `closed` |
| `response` | `avoid`, `mitigate`, `transfer`, `accept` + `actions` |
| `owner`, `category`, `cause`, `effect`, `links` | 담당, 분류(일정·기술·안전·외부 의존·연구), 원인 → 영향, 관련 이슈·문서 |

PI 매트릭스는 점수(가능성 × 영향) 띠로 칠합니다: 1~4 낮음, 5~9 중간, 10~14 높음, 15~25 매우 높음(`bands`로 바꿀 수 있음). arc42 A11의 리스크 표는 같은 파일에서 나옵니다(`<!-- risk-register -->`).

## 5. 스프린트 보드 (`sprints.json`)

메뉴 현황판 › [스프린트](sprints.md) › "스프린트 보드 열기"(전체 화면, `plan/board/`)입니다. 카드는 `scope.yml`의 Backlog와, Backlog 밖의 WBS입니다(Backlog 아래 WBS는 그 카드의 하위 작업으로 보임).

### 5.1 쓰는 법

| 하는 일 | 보드에서 |
| --- | --- |
| 스프린트 계획 | "다음 스프린트 만들기" → 목표 한 문장 → 왼쪽 백로그에서 "할 일"로 끌어 넣기 → "스프린트 시작" |
| 하는 동안 | 카드를 할 일 → 진행 중 → 검토 → 완료로 끌기. 진행 중이 한도(`wip_limit`)를 넘으면 칸이 빨갛게 됨. 막히면 카드를 눌러 막힌 이유를 적음 |
| 마감 (주간 회의 때) | 회고 세 줄(잘된 것, 문제, 다음에 해 볼 것) → "스프린트 마감". 끝나지 않은 카드는 다음 스프린트로 넘어가고(이월) 기록에 남음 |
| 지난 기록 | ◀ ▶ 또는 아래 막대(약속·끝냄)를 눌러 지난 스프린트를 봄. 마감한 스프린트는 회고만 고칠 수 있음 |
| 보기 | "줄: 단계별"이면 칸은 그대로 두고 단계(Epic)마다 가로줄로 나눔(줄 이름을 눌러 접기). "줄: 하나로"는 칸만. 카드 왼쪽 위의 색 글자가 단계 ID(E0, M0 …) |

**이전 스프린트와의 연동**: "스프린트 마감"을 누르면 끝나지 않은 카드(할 일·진행 중·검토)가 같은 칸과 막힘 이유를 유지한 채 다음 스프린트로 넘어가고, 마감한 스프린트에는 넘긴 목록(`carried`)과 완료 카드가 기록으로 남습니다. 다음 스프린트가 없으면 만들고, 미리 만든 계획 스프린트가 있으면 거기에 합칩니다. "다음 스프린트 만들기"는 빈 계획 스프린트를 미리 만들 뿐이고 이월은 마감 때 일어납니다.

**검토 칸**: 손으로 할 일은 끝났고 다른 사람의 확인이 남은 일입니다. 제안 상태 ADR의 승인, MR 병합, 사람이 직접 해야 하는 실행(그런 규칙을 ADR로 정한 경우), VR 재현·사용자 확인. 확인이 끝나 근거(로드맵 done, 이슈 닫힘)가 생기면 완료로 옮깁니다. 검토가 쌓이면 확인이 병목이라는 신호입니다.

끌기 대신 카드를 누르면 오른쪽 패널에서 칸을 고를 수 있습니다(키보드: 카드에서 Enter).

### 5.2 저장

문서 사이트는 정적이라 보드가 파일을 직접 쓰지 못합니다. **개발 미리보기(8001)에서 연 보드만** 저장 서버(docs-kit `bin/plan_board.py`, 8002)를 거쳐 `sprints.json`을 바로 고칩니다. 미리보기가 다시 빌드되고, 고친 파일은 다른 문서처럼 커밋합니다. 공유 사이트(8000)의 보드는 보기 전용이고, "내보내기"로 JSON을 복사할 수 있습니다.

- 저장 서버는 미리보기 포트에서 온 요청만 받고, 값을 검사한 뒤 씁니다. 쓰기 전 파일은 `build/plan/sprints-backup/`에 남습니다(최근 50개).
- 켜는 명령은 `sprints.json`의 `save.start`에 적습니다(보드가 안내에 씀).

### 5.3 근거와 보드의 관계

보드의 칸은 **팀이 일을 어떻게 굴리는지**이고, 현황판의 진척은 그대로 **근거(로드맵 done, 이슈 닫힘)**로 셉니다. 둘이 다르면 카드에 표시됩니다.

| 표시 | 뜻 | 할 일 |
| --- | --- | --- |
| 근거 필요 | 보드에서는 완료인데 로드맵이 done이 아니거나 이슈가 열림 | 로드맵 항목 `done` 또는 이슈 닫기 |
| 완료됨 MM-DD | 근거로는 끝났는데 보드에서는 완료 칸이 아님 | 완료로 옮기기 |
| 막힘 | 카드에 막힌 이유가 있음 | 리스크·이슈와 연결해 풀기 |

### 5.4 파일 형식

```json
{"cadence_days": 7, "wip_limit": 3, "save": {"port": 8002, "from_ports": [8001], "start": ".docs-kit/bin/serve.sh board start"},
 "sprints": [{"id": "S3", "start": "2026-11-17", "end": "2026-11-23", "state": "active", "goal": "…",
              "items": {"B.61": "todo", "W.dashboard": "doing"}, "blocked": {"B.61": "…"},
              "carried": [], "retro": {"good": "", "problem": "", "try": ""}, "note": ""}]}
```

`state`: `planned`, `active`(하나만), `closed`. `items`의 칸: `todo`, `doing`, `review`, `done`. 스프린트 기간은 겹치지 않습니다. 모르는 카드·칸, 겹친 기간, 진행 중 둘 이상은 빌드 경고입니다.

## 6. 이슈 스냅숏 (`issues.json`)

현황판(`issue:` 항목의 상태), 근거 점검(문서 속 `#12`가 있는 이슈인지), 주간 보고 재료(`.docs-kit/bin/weekly_draft.py`)가 이 파일을 읽습니다. 트래커(GitLab, GitHub, Jira 등)에서 받아 쓰는 스크립트는 프로젝트가 둡니다. 없으면 이 파일 없이도 동작합니다(이슈 상태만 빠짐).

```json
{"taken": "2026-11-18T10:54:55+09:00",
 "issues": [{"iid": 12, "title": "…", "state": "opened", "labels": ["task", "docs"],
             "milestone": "업무 이름 또는 null", "created": "2026-11-05", "closed": null}]}
```

`state`는 `opened` 또는 `closed`, `closed`는 닫힌 날입니다. 마일스톤 이름은 주간 보고의 업무 이름과 로드맵 `units`의 이름과 같게 둡니다.
