# 현황판

과제가 **무엇을 얼마나 하기로 했고(계획 작업량), 얼마나 끝냈고(진척), 언제 끝날지(예측)**, 단계마다 통과 기준을 얼마나 채웠는지, 연구 질문에 얼마나 답했는지, 어떤 리스크가 있는지를 한 화면에 모았습니다. 연구 과제라 계획이 바뀌는 것을 전제로 만들었습니다.

??? info "읽는 법과 낱말"

    | 낱말 | 뜻 |
    | --- | --- |
    | 작업량 | 계획에 들어 있는 일의 크기 합(영어로 scope). 일을 더하면 늘고, 빼면 줄어듭니다 |
    | 포인트 | 일의 크기 단위. 1 포인트 ≈ 이상적인 하루 작업(추정, 서로 비교하는 상대 크기) |
    | 폭 | 아직 잘게 나누지 않은 먼 일은 크기를 최소~최대로 적습니다. 그래서 작업량은 선이 아니라 띠로, 끝나는 날은 날짜 폭으로 나옵니다 |
    | 시기 | 지금 / 다음 / 나중. 가까운 일은 잘게 나누고, 먼 일은 다가올 때 나눕니다(연동 계획, rolling wave) |
    | 기준선 | 계획을 크게 다시 정한 날(B0 과제 시작, B1 …). 그래프에 세로선으로 표시 |
    | 통과 기준 | 단계(Epic)를 마쳤다고 말할 조건(stage-gate). ✓ 충족, △ 일부, ○ 미충족 |
    | 완료 정의 | Backlog·WBS 하나를 끝냈다고 말할 조건(DoD) |

    상태는 따로 적지 않고 로드맵 항목과 GitLab 이슈(스냅숏)에서 가져옵니다. 원천 파일과 고치는 법은 [현황판 편집 안내](guide.md)에 있습니다.
