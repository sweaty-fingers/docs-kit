# 주간 보고

팀 회의에서 함께 보는 진행 보고입니다. 날짜가 아니라 **업무(이슈 트래커의 마일스톤) 기준**으로 씁니다. [메모](../memos/README.md)를 골라 주면 그 메모에 적힌 일로 쓰고, 고르지 않으면 **지난 보고를 쓴 날부터 이번 보고를 쓴 날까지**의 커밋·이슈·작업 내역으로 씁니다. 같은 업무는 매 보고에서 같은 이름이라, [업무별 흐름](threads.md)에서 한 업무가 여러 주에 걸쳐 어떻게 왔는지 한 페이지로 읽힙니다.

## 2. 규칙

| 규칙 | 내용 |
| --- | --- |
| 파일 | `docs/weekly/YYYY-MM-DD.md` (쓴 날), 제목 `# YYYY-MM-DD 주간 보고`. 형식은 [템플릿](template.md) |
| 기간 | 머리말 `from`(지난 보고의 `date`) ~ `date`. 첫 보고는 프로젝트 시작일부터 |
| 재료 | 고른 메모가 있으면 그 메모만: `.docs-kit/bin/weekly_draft.py --memos <번호…> --write`(메모 날짜는 기간 밖이어도 됨, 머리말 `memos`에 번호가 남음). 없으면 `.docs-kit/bin/weekly_draft.py --write`(지난 보고 이후의 이슈·커밋·작업 내역) |
| 업무 | `## 3. 업무별 진행` 아래 `### 3.N <업무 이름>`. 마일스톤이 있으면 그 이름, 없으면 정한 이름을 **매 보고 같게** 씀(다르면 업무별 흐름에서 다른 업무가 됨). 자잘한 일은 `그 밖` |
| 업무마다 | **배경**(이어지는 선행 작업·회의 요청을 1~3줄 + 링크), **한 일**(무엇을 왜), **결과**(근거 링크), **다음**. 막혔으면 **막힌 것** |
| 사실 | 보고에 새 사실·결정을 쓰지 않습니다. 결과는 정본(VR·EXP·ADR)과 작업 내역에 먼저 있고, 보고는 링크합니다 |
| 할 일 | 회의 요청과 다음 할 일은 이슈로 남기고 보고에는 번호만 적습니다 |
| 링크 | 보고 안의 `#12`(이슈), `!27`(MR), `VR-0004`·`ADR-0011`·`EXP-0001`·`P-0001`은 저절로 링크됩니다. 절은 `[§4.1](#41-...)`처럼 직접 링크 |
| 상태 | `draft`(작성·검토 중) → 회의 뒤 `published` + `commit`(그 시점 기본 브랜치 커밋). 발행 뒤에는 `## 5. 회의 메모`에 덧붙이는 것만 |
