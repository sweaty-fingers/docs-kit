# 로드맵 편집 안내

로드맵은 `docs/roadmap/roadmap.yml` 한 파일입니다. 그림, 업무별 흐름, 표, 항목별 세부 페이지는 모두 빌드할 때 이 파일에서 만들어집니다(docs-kit `hooks/roadmap.py`). 계획이 바뀌면 이 파일만 고칩니다.

## 1. 파일 구조

```yaml
title: 과제 로드맵
tracks:                         # 트랙 = 세로 레인. 위에서 아래 순서. 합류하는 트랙은 서로 이웃하게 둠
  - {id: core, name: 핵심 기능, color: "#d9534f"}
  - {id: ui, name: 화면, color: "#2f7ed8"}
units:                          # 업무 = 한 흐름으로 읽을 항목 묶음 (선택)
  - {id: mvp, name: 첫 버전, summary: 핵심 흐름이 처음부터 끝까지 돈다}
items:
  - id: api-spike               # 바꾸지 않는 짧은 이름 (세부 페이지 주소가 됨)
    title: 외부 API 사전 검토
    track: core                 # 트랙 하나, 또는 이웃한 트랙 목록 [core, ui] = 둘을 합친 일 (두 레인에 걸쳐 그려짐)
    unit: mvp
    status: done                # done | doing | next | later | future | dropped
    date: 2026-11-13            # done·dropped일 때: 끝난 날 (그 주 칸에 놓임)
    after: [docs-site]          # 앞 작업 (화살표). 다른 트랙의 항목이면 점선
    refs: [ADR-0003, VR-0002, G2, "#60", "!33"]
    summary: 한두 줄 설명
```

## 2. 상태와 칸

| `status` | 놓이는 칸 | 모양 |
| --- | --- | --- |
| `done` | `date`가 든 주 | 채운 상자, ✓ |
| `doing` | 지금 | 굵은 테두리 |
| `next` | 다음 | 점선 테두리 |
| `later` | 그다음 | 점선, 흐리게 |
| `future` | 나중 | 점선, 흐리게 |
| `dropped` | `date`가 든 주 | 회색, 취소선 |

앞으로 할 일에는 날짜를 적지 않습니다. 확신 정도(지금·다음·그다음·나중)로 놓아야 계획이 바뀌어도 한 단어만 고치면 되기 때문입니다.

## 3. 갈라지고 만나기

- **같은 트랙 안의 앞뒤**: 굵은 실선(노선)
- **다른 트랙에서 이어짐**: 점선. 예: 핵심 기능에서 만든 것을 화면이 이어받음
- **합류**: 서로 다른 트랙의 앞 작업 둘 이상이 이어지거나, 여러 트랙에 걸친 일(`track: [core, ui]`)이면 "합류"가 붙습니다. 예: 첫 버전 공개

## 4. 관련 문서 (`refs`)

| 적는 법 | 링크되는 곳 |
| --- | --- |
| `ADR-0003`, `VR-0002`, `EXP-0001`, `P-0001` | 그 문서 (제목이 함께 나옴) |
| `G2`, `R1`, `A3`, `G2 §6.1` | 가이드, 참고, arc42 섹션 |
| `배경 20` | 배경 문서 |
| `"#60"`, `"!35"` | 이슈, MR (`extra.issues_url`). 따옴표 필요 (YAML에서 `#`은 주석) |
| `guides/g2_x.md#anchor` | docs 안의 문서 |
| `https://...` | 그 주소 |

문서로 풀리지 않는 참조는 빌드할 때 경고가 나옵니다.

## 5. 계획이 바뀔 때

| 바뀐 것 | 고칠 것 |
| --- | --- |
| 일이 끝남 | `status: done`, `date` |
| 순서가 바뀜 | `after` |
| 미룸·당김 | `status` (`next` ↔ `later` ↔ `future`) |
| 하지 않기로 함 | `status: dropped` (지우지 않음: 왜 안 했는지 `summary`에) |
| 갈래가 바뀜 | `track` (트랙 추가·순서 변경은 `tracks`) |
| 업무 묶음이 바뀜 | `unit`, `units` |

항목 `id`는 세부 페이지 주소이므로 바꾸지 않습니다.
